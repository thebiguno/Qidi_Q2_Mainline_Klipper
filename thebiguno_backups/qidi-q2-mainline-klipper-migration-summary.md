# QIDI Q2 mainline Klipper migration summary

## From removal of the stock software stack to the current state

The printer has now moved from QIDI’s stock host software/MCU firmware environment to a functioning upstream-mainline Klipper system using the MisterSheikh Q2 patches, Katapult bootloaders, Moonraker/Fluidd, the native load-cell probe, and printer-side startup/safety logic. We have also completed a first successful print.

## 1. Removed the QIDI host software stack and installed a clean upstream stack

We moved the old QIDI/KIAUH environment aside and removed the stock Klipper, Moonraker, Fluidd and Crowsnest installations rather than trying to upgrade them in place.

The stock `klipper-mcu.service` was disabled/moved aside so it could not interfere with the new system.

We then installed:

- fresh KIAUH 6.x
- upstream Klipper
- Moonraker
- Fluidd

Crowsnest was intentionally deferred, and we have not installed KlipperScreen because the intended eventual UI is HelixScreen.

Moonraker successfully came up on port 7125 and Fluidd at the printer’s IP address.

## 2. Pinned and patched upstream Klipper specifically for the Q2

We cloned MisterSheikh’s `Qidi_Q2_Mainline_Klipper` repository and pinned upstream Klipper to the repository’s known-good commit:

```text
9c1ae230eaebd5ec4df76d5a87537e2f35defab0
```

We applied the five normal Q2 patches:

1. GD32F425 USB workaround
2. CS1237 load-cell support
3. Q2 multi-MCU trigger synchronization changes
4. Q2 GD32F303 SPI2 mapping
5. safe GD32F425 MCU-temperature support

We deliberately did **not** apply the optional maximum-clock patches.

## 3. Built and flashed mainline Klipper onto both printer MCUs while keeping Katapult as the bootloader

The mainboard application was built for the STM32F407-compatible target at:

```text
0x08008000
```

The toolhead application was built for the STM32F103-compatible target at:

```text
0x08002000
```

The toolhead continues to use `/dev/ttyS4` at 500000 baud.

Katapult remains installed underneath both applications, so normal future firmware updates can use the bootloader rather than ST-Link.

Verified Katapult application starts:

```text
Mainboard: 0x08008000
Toolhead:  0x08002000
```

## 4. Migrated the Q2 configuration to mainline Klipper rather than replacing it wholesale

We created multiple point-in-time backups before editing.

Changes included:

- disabled `[include MCU_ID.cfg]`
- replaced it with a direct `[mcu]` using the new Klipper USB by-id path
- retained `[mcu THR]` on `/dev/ttyS4`, 500000 baud
- disabled stock `plr.cfg`
- disabled stock `box.cfg`
- retained useful Q2 machine configuration
- removed QIDI-only Z stepper reverse-endstop options
- retained `endstop_pin: probe:z_virtual_endstop`
- changed MAX6675 SPI bus to `spi2_PB14_PC0_PB13`
- removed the QIDI-only chamber `z_max_limit`
- replaced `[probe_air]` with mainline `[load_cell_probe]`

## 5. Resolved mainline configuration/parser incompatibilities and got both MCUs fully connected

We removed the QIDI-only:

```ini
[motor_constants qidi_x_y]
```

and avoided using the old autotune-TMC configuration.

We added a mainboard temperature sensor using `temperature_mcu`; the patched firmware correctly advertises the GD32F425 temperature type.

We also added MisterSheikh’s `utility_macros.cfg`.

An early `SAVE_CONFIG` failure was traced to a normal config section accidentally sitting below Klipper’s autogenerated `SAVE_CONFIG` marker. That section was moved above the marker and subsequent saves succeeded.

Both MCUs then reached Klipper’s normal `ready` state.

## 6. Converted the Q2 load cell to native mainline Klipper and calibrated it

Initial CS1237 diagnostics were clean:

- roughly 1250 samples/s
- zero saturated samples
- very low unloaded noise

We calibrated the load cell against a 989 g reference mass.

Persisted calibration:

```ini
counts_per_gram: 235.048534
reference_tare_counts: -673782
```

`LOAD_CELL_TEST_TAP` detected all three taps correctly.

We then successfully used the load cell as the Z probe for real homing.

## 7. Commissioned motion, Z probing, Z tilt and bed meshing

X/Y homing and movement were tested first, followed by real:

```gcode
G28 Z
```

`Z_TILT_ADJUST` completed with only about 0.001 mm difference between its two measured points, well inside the configured 0.05 mm tolerance.

We also ran a temporary 3×3 mesh using native bed-mesh calibration.

Repeatability between duplicate probe samples was only a few thousandths of a millimetre.

The temporary mesh showed roughly 0.186 mm total bed variation and was not saved as a production mesh.

## 8. Commissioned every heater, temperature sensor, fan and the extruder

Ambient readings for the hotend, bed, chamber, chamber-protection sensor and mainboard MCU were sensible.

### Hotend

- heater worked
- inherited stock PID overshot during the initial low-temperature test
- automatic heatsink fan switched on at about 50 °C
- fan switched back off below 50 °C

### Bed

- heated normally
- little/no overshoot
- no unexpected fan activity

### Chamber

- chamber heater behaved normally
- controlled chamber sensor reached about 30 °C
- separate thermal-protection sensor rose much faster to about 60 °C
- chamber-heater fan operated correctly

### Fan mapping

Physical fan mapping was established as:

```text
chamber_circulation_fan -> rear exhaust / vent fan
cooling_fan             -> nozzle part-cooling fan
auxiliary_cooling_fan   -> upper-right side blower
```

### Extruder

The extruder passed:

```gcode
STEPPER_BUZZ STEPPER=extruder
```

and later passed a real filament-feed/extrusion test.

## 9. Retuned the hotend PID under mainline Klipper

We ran:

```gcode
PID_CALIBRATE HEATER=extruder TARGET=220
```

Mainline Klipper produced and saved approximately:

```text
Kp = 33.879
Ki = 3.828
Kd = 74.958
```

This replaced the inherited stock tuning.

## 10. Removed the remaining stock-QIDI dependencies from the critical print macros

The original `PRINT_START`, `PRINT_END`, `CANCEL_PRINT`, `PAUSE` and `RESUME_PRINT` still referenced QIDI-specific components such as:

```text
BUFFER_MONITORING
box_extras
save_last_file
DISABLE_BOX_HEATER
CLEAR_LAST_FILE
box_stepper
```

We replaced the critical macros with MisterSheikh’s current mainline-adapted versions and added the required `_Z_CLEARANCE` helper.

We disabled the legacy KAMP include and moved to Klipper’s native adaptive bed meshing.

`M141` and `M191` were retained because they are straightforward wrappers around mainline chamber-heater commands.

We also removed the obsolete `DISABLE_BOX_HEATER` call from `[idle_timeout]`.

## 11. Simplified OrcaSlicer so the printer owns machine-specific behaviour

Orca’s Machine Start G-code was reduced to essentially:

```gcode
SET_PIN PIN=caselight VALUE=1
PRINT_START BED=[bed_temperature_initial_layer_single] HOTEND=[nozzle_temperature_initial_layer] CHAMBER=[chamber_temperature]
SET_PRINT_STATS_INFO TOTAL_LAYER=[total_layer_count]
G90
M83
```

Machine End was reduced to:

```gcode
PRINT_END
SET_PIN PIN=caselight VALUE=0
```

The old QIDI purge motions, Box tool-change code, PLR calls and elaborate timelapse parking were removed.

Orca-generated G-code correctly emits `EXCLUDE_OBJECT_DEFINE` before `PRINT_START`, so native `ADAPTIVE=1` bed meshing receives the model footprint.

We also discovered that Orca 2.4.2’s **Use 3mf instead of g-code** option prevented Upload & Print from actually starting the job with this Moonraker setup. Turning that option off fixed it.

## 12. Completed the first real mainline-Klipper print

The first cube printed successfully.

Observed results:

- overall print quality was good
- mild ringing near box edges
- first layer was mostly fine
- old filament stuck to the nozzle disturbed part of the first layer

The generated Orca file was initially commanding 10000 mm/s² travel acceleration.

This sounded noticeably harsher / grittier than expected.

Manual testing during the print showed 6000 mm/s² sounded substantially smoother.

Driver temperatures during the first print were roughly:

```text
X driver: just under 70 °C
Y driver: just under 60 °C
```

with the top cover removed.

## 13. Moved the acceleration safety limit into Klipper itself

The `[printer]` configuration originally contained:

```ini
max_accel: 20000
```

We changed the startup/default value to:

```ini
max_accel: 6000
```

Because Klipper permits slicers to change the runtime limit with `SET_VELOCITY_LIMIT` or `M204`, we also wrapped `SET_VELOCITY_LIMIT` and clamp any requested `ACCEL` to a maximum of 6000.

The existing Q2 `M204` macro already funnels acceleration changes through `SET_VELOCITY_LIMIT`, so it inherits the same ceiling.

Verified behaviour:

```text
SET_VELOCITY_LIMIT ACCEL=10000 -> max_accel 6000
M204 S10000                    -> max_accel 6000
M204 S3000                     -> max_accel 3000
```

This gives us a printer-side mechanical policy independent of slicer, computer or profile.

## 14. Developed and validated a new printer-side nozzle-cleaning sequence

We physically mapped the Q2 rear service area rather than blindly restoring the old stock macro.

### Purge chute / claw / roller geometry

Approximate service positions:

```text
X90 Y287.5  -> purge chute
X96-X103    -> scraper / claw
X103-X115   -> roller
```

The chute-release mechanism behaves like a one-way gate:

- enter the rear area from the front by increasing Y
- once past the trigger, continue moving right
- do not move left again until moving forward to about Y270

The chute/claw/roller assembly is frame-mounted, not bed-mounted.

Therefore Z remains safely at:

```text
Z5
```

during those operations.

### Silicone pad geometry

The silicone wiping pad was physically mapped and tested.

Validated wipe geometry:

```text
X166 <-> X182
Y287
Z-2
F2000
```

This gives good contact while remaining clear of the bed edge and right-side wall.

### Heated cleaning cycle

The tested cleaning sequence now:

1. homes
2. moves to purge chute
3. heats to requested hotend temperature
4. purges 25 mm total
5. retracts 2 mm
6. cools toward 140 °C with the part fan running
7. waits until <=175 °C
8. wipes the scraper/claw at X96<->103, F3000
9. wipes the roller at X103<->115, F2000
10. exits only to the right
11. waits until <=150 °C
12. wipes the silicone pad at X166<->182, Y287, Z-2, F2000
13. lifts
14. returns through the safe Y270 corridor

This was installed as:

```gcode
QIDI_NOZZLE_CLEAN HOTEND=<temperature>
```

and successfully tested.

## 15. Integrated nozzle cleaning into `PRINT_START` before precision Z probing

The startup sequence now deliberately performs an initial home so cleaning motions are safe, then executes the nozzle cleaner.

After cleaning, the nozzle is brought to the controlled probing temperature of 140 °C and Z is homed again:

```gcode
M109 S140
G28 Z
```

That second Z home is the important precision reference.

This means any filament blob present during the initial home is removed before the load-cell probe establishes the Z reference used for the print.

After that:

```text
Z_TILT_ADJUST
adaptive BED_MESH_CALIBRATE
```

are performed with the clean nozzle.

The final `M204 S10000` from the reference macro was also changed to:

```gcode
M204 S6000
```

to reflect the new machine acceleration policy directly.

## 16. Re-created the Q2 front purge lines in a safer mainline form

The Q2 has a front build-plate strip that protrudes beyond the normal print area.

We manually tested two purge lines there using approximately:

```text
First line:  X108 -> X153 at Y1
Second line: X108 -> X153 at Y2.5
Z height:    0.20
```

The new purge routine deliberately does **not** restore the stock relative:

```gcode
G1 X1 Z-0.300
```

scraping move.

The current tested purge-line macro is:

```ini
[gcode_macro QIDI_PURGE_LINES]
description: Two purge lines on the Q2 front build-plate extension
gcode:
    SAVE_GCODE_STATE NAME=QIDI_PURGE_STATE

    G90
    M83

    # First purge line
    G1 X108 Y1 Z0.20 F6000
    G1 X128 E8.0 F600
    G1 X153 E2.0 F1200

    # Lift before moving to second line
    G1 Z1.0 F600
    G1 X108 Y2.5 F6000
    G1 Z0.20 F600

    # Second purge line
    G1 X128 E10.0 F600
    G1 X153 E2.0 F1200

    # Leave nozzle safely above the plate
    G1 Z1.0 F600

    RESTORE_GCODE_STATE NAME=QIDI_PURGE_STATE
```

The manual test looked good.

The intended placement is at the end of `PRINT_START`, after final hotend heating and `set_zoffset`, immediately before actual printing.
